# Active project goal

Activated on 2026-09-27 at the user's request. Complete a reproducible local-first investigation of whether typed semantic judge features improve the choice of reasoning interventions. Use frozen open-weight generators and independent executable outcome checks. The Jev account allocation is a **$25 total ceiling**, with staged caps in `configs/stages.json`; expenditure is not a research target.

## Work packages and acceptance evidence

1. **Compute and instrumentation.** Verify the existing Mac SSH pool, qualify actual resources, preserve peer work, and retain bounded job receipts. Check exact prefixes, online eligibility, failed attempts and discarded-work accounting. The lead runs the already qualified MLX generator; remote assignment requires its own runtime/resource qualification.
2. **Theory and prior art.** Maintain the pinned source audit, explicit checkpoint/full-episode estimands, proofs with assumptions, and independent review. Numerical examples check formulas and counterexamples; they are not proofs of real-model benefits. Do not claim standard intervention-value or information-value results as original.
3. **Development.** Run fresh baseline/sham episodes using the frozen `development_v1.json` settings. Inspect usable unfinished reasoning and final success without querying Jev or opening test tasks. Record every sampled problem, including early completion and ineligibility. Prompt/task changes require a new development version.
4. **Mechanism screen.** Once instrumentation and task variation are usable, collect 24 fresh problems, three fixed actions and four prespecified continuations per action. Query the same typed schema for Jev and an independent local judge. Compare identical learners, strong cheap text features, constant actions, and fixed heuristics. Keep this stage exploratory and group by original problem.
5. **Decision and validation.** Replicate uncertain action differences on fresh fixed-count continuations when informative. Freeze selected policies before a separate prospective deployment evaluation. Escalate to the pilot, sequential control or transfer only when preceding results justify it. A negative or inconclusive screen must report its precision and does not establish arbitrary absence of benefit.
6. **GitHub release.** Publish tested implementation, frozen configurations, theory/review, aggregate measured results, source hashes and limitations. Keep credentials, private host registry, budget database and raw hosted-judge responses outside Git. Public/synthetic local model traces can be released separately with manifests when ready.

## Completion criteria

The project is complete when the qualified experimental branch reaches an evidence-supported decision, remaining claims are scoped accordingly, theory and implementation reviews are resolved, and a reproducible report/code release is published. A positive Jev effect is not required. Failure of a measured gate can end an expansion, but a fixable instrumentation bug is not evidence against the hypothesis. An unavailable resource or incomplete evaluation is reported as outstanding work, never counted as successful completion.

Current goal status is maintained by Codex. This document records scientific scope; it does not assert that all work packages have finished.
