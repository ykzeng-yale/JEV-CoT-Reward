# Arithmetic opportunity screen v1

Development-only feasibility stage, frozen September 29, 2026, before generation. The prior correction test found only five arithmetic-construction cases among 25 selected erroneous-equality checkpoints, too few to estimate family-specific effects. This screen estimates whether fresh arithmetic-construction traces produce enough naturally expressed, locally checkable addition claims to justify a matched intervention study.

Generate the first 256-token paragraph checkpoint for 120 fresh procedural arithmetic-construction tasks. Task indices are the odd integers 1 through 239 under task seed 81277919. The generator is pinned Qwen3-4B-Instruct-2507, MLX four-bit, temperature .7, top-p .9. Each task gets at most 384 generated prefix tokens, without gold answer access. Retain and report all ineligible tasks. In each eligible latest segment, parse the first explicit integer addition equality `a+b=c`; classify it as correct or incorrect by Python integer arithmetic. Absence of such a statement is recorded as no observable opportunity. No Jev calls, terminal outcome inspection, or outcome-based enrollment occurs.

The screen does not estimate whether a judge detects errors or whether correction improves answers. It only gates whether the natural event rate supports a follow-up. Advance to a separately frozen, fresh matched-action qualification only if at least 20 incorrect equations are found and all are auditable from exact token prefixes. Otherwise redesign the task family/checkpoint protocol before allocating outcome rollouts. Never convert the screen rate into a broad population estimate: it is conditional on these tasks, model, prompt, sampling settings and checkpoint eligibility.

Budget: one local MLX model process, 7,200-second cooperative wall bound, 7,350-second external bound, 8 GiB sampled-RSS ceiling, 32 MiB combined log ceiling, no hosted judging or download. This study cannot support efficacy, calibration, transfer or innovation claims.
