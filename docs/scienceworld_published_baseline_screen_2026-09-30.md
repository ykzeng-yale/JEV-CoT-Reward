# ScienceWorld published-controller screen — September 30, 2026

## Purpose

The question is whether the Mendelian candidate has a defensible, executable comparison baseline before any model runs. This is a primary-source bibliography screen, not an implementation audit, reproduction, or performance result.

The ScienceWorld paper itself also reports interactive agents and established task baselines; its source and benchmark contract are cited in `paper/main.tex`. The three methods above are sufficient to reject a broad claim that applying stepwise evaluation, trajectory reward, or iterative critique to ScienceWorld is new. They do not establish that the narrower matched-prefix empirical estimand has been evaluated; that possible distinction remains a candidate question only and needs a more exhaustive literature/code review.

## Decision and required follow-through

1. Do not describe the ScienceWorld task as a novel benchmark, controller, or scientific-discovery method.
2. Before any agent comparison, pin and inspect official repositories/artifacts for versions, license, checkpoint/data availability, exact task splits, inference interface, and resource needs. ARMAP's complete-trajectory/restart policy, custom JAR, and 10-step-vs-Mendelian-horizon mismatch must be resolved; preserve its upstream commit and any port diff.
3. Select at least one compatible published controller if code/checkpoints permit. For a same-prefix action-value estimand, a full-trajectory reward scorer must be explicitly adapted to score all candidate continuations from the exact shared prefix; keep a separate end-to-end ARMAP reference if budgets allow. Use the same actor backbone, frozen task split, checkpoint builder, candidate actions, continuation policy, terminal evaluator, deadlines, and complete cost ledger where technically possible. If original methods cannot be matched, label any port as an adaptation and report original published results only as context, not as head-to-head evidence.
4. Keep the independent target narrow: fixed-prefix terminal classification outcomes for a predeclared action, under full acquisition and continuation costs, compared with a strong action-specific local controller and static/sham/randomized controls. A method-level novelty claim remains unsupported.

This screen did not run a model, access hidden test outcomes, use Jev, or establish efficacy. It only strengthens the prior-art gate and changes the baseline obligations for the candidate.

## September 30, 03:12 EDT — pinned ARMAP code and checkpoint contract

I cloned the official repository and checked out commit `9a240bbb718b05ad72145dfa75be9a77aa942f14` (detached); source files were inspected locally, not executed. The ScienceWorld `main_re.py` converts a **completed episode's full history** into an evaluator request, appends the query “Please evaluate whether you complete the Task Description or not,” and reads one scalar reward. The threshold (`7.25` in the published Llama-8B example) stops or triggers a fresh environment attempt; a failed attempt also elicits a new-plan reflection. The released policy therefore does not score candidate actions from one shared prefix. Branch-scoring it would be a new adaptation, even though a terminal-trajectory scorer could technically be called on each completed branch.

The released `RM-sciworld/checkpoint-120` is a BF16 `RewardModel` with a VILA1.5-3B backbone and a rank-64 LoRA over the attention/MLP projection modules; its checkpoint metadata names Transformers 4.30.2. The adapter config's base-model path is an author's local VILA directory, so deployment requires resolving and pinning the corresponding public base weights and matching the authors' LLaVA/VILA modifications. The scorer also uses the repository's multimodal request format (including a constant placeholder image) and caps/rejects long converted histories. The ScienceWorld training script uses `sciworld_preference.json`, performs 10 training epochs, and carves 500 evaluation examples from that same file. The public HF model and dataset are Apache-2.0; model revision `74749604af69a8f67668622610351de9ed79ba23`, dataset revision `2ad18b4816346d251857dbd5685a80292219fc2d`.

The frozen aggregate-only scan of that exact public preference file verified 17,731,424 bytes and SHA-256 `0fa73e44655c383ec5c85dcf81fed041f7ca3c87877329a680c7f5c28a8db883`. It contains 4,064 records with schema keys `conversations`, `id`, `image`, `output_1`, `output_2`, and `preference`; `id` is the only identifier-like key, and no explicit task-variation field or held-out variation ID was found. The scan found the terms `dominant` and `recessive` in two records each (the two terms occur in the same two records), alongside broader plant/seed language. This is a task-domain exposure warning, **not proof** that the exact Mendelian task or any held-out variation appeared. Because the released corpus has no task/variation provenance fields, it cannot certify sample-level disjointness. The aggregate result is `results/armap_sciworld_train_overlap_v1.json`; the frozen protocol and output-redacting scanner are `configs/armap_sciworld_train_overlap_v1.json` and `scripts/audit_armap_sciworld_train_overlap.py` (three focused tests pass). No raw example text, preference values, labels, scores, or trajectories are written by the scanner.

This creates two distinct comparability questions. First, the ARMAP checkpoint is a plausible **published end-to-end comparator** for task-completion-guided retry, but it is not a same-prefix action-value baseline. Second, because its reward model was trained on ScienceWorld preference trajectories and its released dataset has no task/variation provenance, exact overlap with the Mendelian candidate cannot be ruled out from the published artifact. The topical hits strengthen the reason to keep this checkpoint out of the primary independent comparison until exact provenance is supplied or independently reconstructed without opening our held-out outcomes. A clean ARMAP-style baseline trained only on permitted official training variations remains a possible adaptation, with its training and scoring costs charged. The published task-success prompt is closer to the Mendelian classification endpoint than aggregate simulator reward, but it does not replace our independently implemented terminal classifier or prove variation disjointness. The project's 117 remaining outcome-unseen test variations stay sealed; do not inspect their labels or trajectories for this audit.
