# Jev natural addition diagnostic v1

Frozen September28 after partial matched perturbation study. This uses all 48 naturally occurring first explicit `a+b=c` claims in the completed, audited repair-v3 and sham-v4 development checkpoints. A Python integer checker defines 23 true and25 false labels (verify at construction). No synthetic edits in this study, no final gold task answers or continuation outcomes in the API state. Deterministically shuffle all48 cases before API calls to reduce label-order bias if service availability interrupts the run. The question is identical to the earlier paired rubric, pinned Jev1.13.0, existing single ledger/$1 stage and $25 hard cap. No retry of an unresolved identical request.

Primary descriptive endpoints: AUROC for true versus false natural equality; threshold0.5 sensitivity/specificity; classwise mean scores, calibration description and request costs. Also report available complete-case sample if a service failure stops collection, including missing labels; do not call an incomplete sample full. These outputs test a narrow arithmetic sensor only, not intervention value or task outcome improvement. Already-cached identical requests remain cache hits and are disclosed.

The paired perturbation diagnostic stopped after29requests due one HTTP503;14 full pairs showed correct-minus-corrupted mean0.156,13/14 positive, but all14 corrupted scores exceeded0.5. That result motivated this natural-error test; it is exploratory, not pre-registered confirmation. If HTTP503 recurs, stop and retain reservation/records, then report actual service blockage. Do not alter query wording after seeing scores.
