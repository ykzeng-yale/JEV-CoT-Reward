# ScienceWorld conductivity duplicate-input label audit

Protocol: `scienceworld_conductivity_duplicate_observation_label_consistency_v1`.

The prior, independently audited visible-index screen found 6 uniquely decoded combinations among the 450 official development variations (2/300 train and 4/150 dev). Its observation digests showed only 113 unique initial observations; 29 exact observation hashes crossed the train/dev boundary and covered 361/450 rows. In particular, 120/150 dev rows repeat an exact initial observation from train, leaving 30 train-novel dev observation hashes. The digest audit did not read labels, so it could not determine whether identical controller inputs had conflicting hidden targets. Upstream result SHA-256: `b88cb8842f5021dca328a0d2c8d323edf509e7e48c0da04f966211f98740d243`.

This follow-up answers that unresolved validity question. Using pinned ScienceWorld source revision `e8216d6044e8e39be9fcb185e3b2dfb602584b52`, it loads only official train variations 0–299 and dev variations 300–449, captures the reset-time controller observation, and reads the source-defined `unknownIsConductive` task modifier only to compare labels for identical observation hashes. It never loads test variations 450–599 and does not access scores, rewards, agent actions, model outputs, Jev, network services, or gold paths.

The output contains split and variation IDs, SHA-256 observation digests, and a Boolean stating whether each row's source label agrees with the lowest-ID row having that exact observation. It never writes the label bit or raw prompt/observation. A second independent script replays all 450 variations from the pinned source and verifies the record-level digests and label-consistency flags before emitting aggregate group counts. This is a source-validity audit, not model accuracy, efficacy, or evidence of information-action benefit.

The RNG ordering is pinned explicitly: `PythonInterface.doLoad` seeds by `variationIdx` before rebuilding `TaskMaker1`; `TaskElectricalConductivity2` constructs the randomized unknown-substance objects in that rebuild. Thus visible recovery of a variation index could expose the seeded label through source reconstruction. The duplicate-input audit additionally tests whether repeated exact observations map to consistent targets. If conflicts occur, the task has an observation-identifiability defect for those groups; if no conflicts occur, that supports only deterministic consistency under this pinned runtime and split, not absence of other source leaks or transfer validity.

The frozen machine-readable specification is `configs/scienceworld_conductivity_duplicate_observation_label_consistency_v1.json`. The run is bounded to one normal-tier `pi_fl426` CPU job, 4 CPUs, 16 GiB RAM, 45 minutes, no GPUs, 2 MB result cap, and 60 MB total run bundle cap. The final evaluation split remains sealed.
